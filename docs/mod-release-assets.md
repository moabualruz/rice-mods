# Product mod release assets and limits

Use this recipe in each product's own release pipeline. It describes assets for
one versioned mod directory; it does not replace the product release or sign
artifacts itself.

## Required assets

For every product mod release, publish:

1. A deterministic plugin ZIP containing the versioned mod directory, including
   its `LIMITS.md`, and no unrelated build output. Use the shared Rice Release
   `plugin.sh zip` producer and its canonical `PRODUCT_VERSION_any_all.zip`
   filename; do not introduce a second archive format or packager.
2. `checksums.txt`, containing the ZIP's SHA-256 digest in lowercase hexadecimal
   and the exact ZIP filename. The verifier must reject missing, malformed,
   mismatched, or duplicate entries.
3. A detached minisign signature for `checksums.txt`, produced by the release
   pipeline's key-based signing step in no-transparency-log mode. The signed
   checksum binds the signature to the ZIP digest. Build unsigned in CI; sign as
   an operator step on a trusted host using configured OpenBao references.
   Publish the public verification key through the product's established
   key-distribution channel. Never put private key material in the archive or
   release assets.
4. A CycloneDX SBOM for the mod's dependency tree, generated by the shared Rice
   Release `plugin.sh sbom` producer from the exact release inputs.
5. The committed native capability baseline from `claude plugin validate
   --json`, bound to the exact mod version and qualified Claude Code version.

Bind every asset digest in the release notes to its exact filename. Before
installing a plugin, run that product's `mod verify` with the release ZIP,
`checksums.txt`, detached signature and trusted public key. Install only after
verification exits successfully. Verification must fail closed; a flipped-byte
archive must fail.

## Per-mod documented limits

These limits reflect the current source documentation and scope. Every versioned
mod directory must include a `LIMITS.md` with its product row from this table and
any release-specific changes; the file must ship inside the plugin ZIP. Release
notes must preserve the limits and add the exact qualified Claude Code version
and baseline. Do not claim a platform or API surface that the product mod does
not implement and qualify.

| Product mod | Managed-policy behavior | Safe-mode behavior | Takeover default | VS Code panel | Claude cloud | Early-access API |
| --- | --- | --- | --- | --- | --- | --- |
| Catalog | Fresh product policy guard owns refusal; plugin Enforce is off by default and cannot replace product policy | Safe-mode and Catalog-worker suppression are unqualified; no suppression claim | No takeover option or default documented; do not claim takeover | Not provided or qualified | Not provided or qualified | No supported early-access API named; host-version changes require qualification |
| Review | No product mod source or README is present in rice-observe origin/main; behavior is unqualified | Unqualified | No mod or takeover default documented | Not provided or qualified | Not provided or qualified | No supported early-access API named |
| Index | MCP owns identity and ACL; hooks are advisory, not an ACL boundary | No safe-mode behavior qualified | No takeover option or default documented; `hint` is the mod mode default | Not provided or qualified | Not provided or qualified | No supported early-access API named; host-version changes require qualification |
| Edit | Native permission flow remains intact; observer records metadata and does not mediate Bash, other MCP or outside-process writes | Disabling hooks, safe mode, unloaded mod and outside-process writes are not mediated | Off by default; explicit enablement is refused as unqualified | Not provided or qualified | Not provided or qualified | No supported early-access API named; host-version changes require qualification |

Review has no source mod in the current rice-observe base, so it must not be
packaged as a supported mod until its implementation and limitations exist.
These entries do not substitute for release-specific qualification evidence.
